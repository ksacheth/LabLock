Solution

Problem
An incident can't be traced — no correlation id, no DB-aware health, secrets read ad-hoc — and there's no Dockerfile or CI to ship or gate the code.

Solution
Deepen two modules — a typed config validated at boot and a requestContext that stamps an id onto every log and error — then add Dockerfile, compose and a CI workflow.

  • request-id on every log + error
  • typed config validated once at boot
  • /health pings the database
  • Dockerfile + CI — enabling infra
Top recommendation

Start with #1 — the Judge behind a sandbox seam.

It is the one cut that pays in every direction the brief asks for: it carves the largest deep module out of the monolith, closes the most serious security hole (untrusted code on the host), and turns the hardest-to-test logic into one interface that takes fixtures and returns a verdict. It is also the single most resume-legible subsystem in the codebase — "I built a sandboxed code judge" reads better than any refactor.

Natural pairing: #5 (in-memory repository adapter) is the enabler that lets the Judge — and #2, #3 — be tested without a live Postgres. If you'd rather show breadth first, #2 (authorization seam) is the cheapest high-leverage win.
